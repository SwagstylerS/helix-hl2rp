# Untested Code

Code committed in remote sessions that has not yet been verified on a live server.

**Adding an entry:** append a row when committing a new feature or fix. Include the minimum
concrete test that would let you confidently remove the entry.

**Removing an entry:** delete the row after a live-server session confirms the behaviour.
Note the verification date and who ran it in the commit message (`verify: <feature> confirmed`).

**Priority:**
- **P1** — blocks further development; a bug here silently corrupts new features built on top of it.
- **P2** — player-facing loop completeness; players notice the gap, but other systems still work.
- **P3** — polish or edge case; low visible impact, safe to defer.

1. **Jun 28 — Heat decay timer** (`CS_HeatDecay`): validate that heat scores decrease on schedule and the sterilized floor holds. Every tier-threshold test below is meaningless if decay is broken.

2. **Jun 28 — Heat tier 4 alert to Combine** (`AddHeat`): with decay confirmed working, push a citizen to Tier 4 and confirm the broadcast fires. This validates that `GetCombinePlayers` and `FindPlayerBySteamID` ordering is correct.

3. **Jun 25 — Scanner pirate_radio flag fix**: scan a CWU worker carrying `cwu_radio` and confirm no false positive. Scan a worker carrying `pirate_radio` and confirm it IS flagged. Establishes the scanner as a reliable instrument before testing what it detects.

7. **Jul 6 — Lockpick pick-lock mechanic**: with the item confirmed scannable and heat working, test all three roll outcomes. Confirm heat increments on success and noise-fail but NOT on quiet-fail — this is the Pillar 5 risk/reward invariant.

8. **Jul 8 — Scanner charger entity**: with battery system confirmed working via scanner tests, validate the entity recharge flow, persistence across map restart, and the non-Combine lock-out.
